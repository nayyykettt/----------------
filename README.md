# Погодный планировщик

Локальный календарь в стиле Google Calendar. Он расставляет гибкие задачи (тренировка, прогулка, магазин, учёба) по лучшим слотам недели с учётом погоды, сна и профилей активности. ТЗ лежит в `ТЗ Погодный планировщик.md`.

## Приложение для macOS

```sh
./build_app.sh
```

Скрипт соберёт «Погодный планировщик.app» в /Applications (Python и pywebview кладутся внутрь, папка проекта после сборки не нужна). Приложение открывается в своём окне, ищется через Spotlight и Launchpad, его можно закрепить в Dock. Данные хранятся в `~/Library/Application Support/Погодный планировщик/data.sqlite3`. При первом запуске туда копируется `data.sqlite3` из папки проекта. После изменений в коде запустите `./build_app.sh` ещё раз, данные при этом сохранятся.

## Сборка под все платформы: macOS, Windows, Linux, Android, iOS

Приложение собирается через [BeeWare Briefcase](https://briefcase.readthedocs.io), настройки — в `pyproject.toml`, обёртка — в `weather_planner/app.py`. На каждом устройстве внутри приложения работает тот же сервер планировщика, а окно показывает его страницу. Сервер слушает только `127.0.0.1`, наружу ничего не открывается, данные остаются на устройстве. Погода, как и раньше, берётся из Open-Meteo, для неё нужен интернет.

Установка Briefcase (один раз): `.venv/bin/pip install briefcase==0.4.6`.

| Платформа | Где собирать | Команда | Что получится |
|---|---|---|---|
| macOS | на Mac | `briefcase package macOS --adhoc-sign` | `dist/*.dmg` |
| Windows | на Windows 10/11 | `briefcase package windows` | `dist/*.msi` |
| Linux | на Ubuntu/Debian (есть варианты для Fedora, openSUSE, Arch) | `briefcase package linux system` | `dist/*.deb` |
| Android | на любой из трёх систем | `briefcase package android -p debug-apk` | `dist/*.apk` — ставится на телефон напрямую |
| iOS | только на Mac с Xcode | `briefcase run iOS` (симулятор) или `briefcase open iOS` | проект Xcode |

Без Windows- и Linux-машины собрать всё можно в GitHub: вкладка **Actions → Сборка → Run workflow** (`.github/workflows/build.yml`). Через 15–30 минут установщики для macOS, Windows, Linux и Android появятся в разделе Artifacts этого запуска. iOS там только проверяется: на iPhone приложение ставится из Xcode. Для этого выполните `briefcase open iOS`, в Xcode выберите свой телефон, в Signing & Capabilities укажите свой Apple ID и нажмите Run. С бесплатным Apple ID приложение работает 7 дней, потом его нужно поставить заново.

Особенности:
- Данные на macOS лежат в той же папке, что и у `build_app.sh`, так что обе сборки видят одни задачи. На остальных системах — в папке данных приложения, своей на каждом устройстве. Синхронизации между устройствами нет.
- На macOS файл приложения называется `Weather Planner.app`: codesign не подписывает приложение с кириллицей в имени исполняемого файла. В Dock и меню показывается «Погодный планировщик».
- На телефоне по умолчанию открывается вид «День», боковая панель свёрнута. Настройки шаблона открываются нажатием на его название: правого клика там нет.
- Значки лежат в `icons/`, сгенерированы из `icon.svg`.

## Запуск из терминала (для разработки)

```sh
./run.sh
```

Нужен только Python 3.9+. При первом запуске скрипт создаст `.venv` и поставит одну зависимость (`python-dateutil`), затем откроет в браузере http://127.0.0.1:8765/. Порт можно сменить: `PORT=9000 ./run.sh`. Чтобы браузер не открывался, добавьте `--no-browser`.

Данные лежат в `data.sqlite3` рядом с кодом и сохраняются между запусками. Чтобы начать с нуля, удалите этот файл.

Для прогноза и поиска города нужен интернет: используется Open-Meteo, бесплатно и без ключей. Календарь (FullCalendar) лежит в `static/vendor` и от интернета не зависит.

## Тесты

```sh
python3 -m unittest discover -s tests -t .
```

`tests/test_scheduler.py` проверяет алгоритм: пересечения с учётом буферов, сон, окна «с/до», запрещённые дни, начало позже текущего момента, горизонт прогноза, погодные пороги, интервал между задачами одного шаблона, мягкое окно профиля, «лучшие из худших», приоритеты и автоперенос (по погоде и при перекрытии событием; закреплённые задачи не двигаются). `tests/test_calendar.py` проверяет разбор .ics (RRULE, EXDATE, TZID, RECURRENCE-ID), совмещение импортов, удаление одного вхождения, разделение серии «это и последующие» и сохранение данных.

## Как пользоваться

- **Событие:** выделите время мышью в виде «День» или «Неделя». Клик по событию открывает редактирование, его можно перетаскивать и растягивать. У повторяющихся событий при изменении спрашивается, что менять: «только это», «это и последующие» или «вся серия».
- **Задача:** перетащите шаблон из левой панели в календарь или нажмите «+». В календаре подсветятся 3–5 вариантов (пунктир), клик по варианту ставит задачу. Пока задача не поставлена, она висит в «Не размещены» с указанием причины. Кнопка «Расставить» размещает все такие задачи по приоритету.
- **Шаблон:** нажатие на название (или правый клик) открывает настройки, «+» у заголовка создаёт новый шаблон.
- **Закрепление:** задача, перетащенная мышью, закрепляется (🔒). Клик по задаче открывает меню, где закрепление можно снять, подобрать другое время, убрать задачу из календаря или удалить её.
- **Проверка автопереноса:** в «Настройках» есть кнопка «Подменить прогноз: дождь». Дождь ставится везде, кроме последних 2 дней прогноза, чтобы задаче было куда переехать. Незакреплённые задачи переносятся, появляется плашка, а задача подсвечивается до клика по ней. Закреплённые задачи остаются на месте и получают ⚠.

## Решения по неясным местам ТЗ

- **Ветер** сравнивается по **средней** скорости. Порывы видны в подсказке у часа.
- **«Мин. интервал, дней» = N** — это N полных дней между задачами. При N = 1 соседние дни считаются нарушением, как в критерии приёмки.
- **Погода** проверяется только на время самой задачи. Сон и занятость проверяются вместе с буферами. Буферы двух задач тоже не должны пересекаться.
- **Окно профиля активности** — мягкое правило: слот вне окна попадает только в «лучшие из худших».
- **Горизонт** — 7 дней прогноза Open-Meteo. Задачи без учёта погоды тоже ставятся только в пределах этого горизонта.
- **Сон:** «отбой» — вечер этого дня, «подъём» — утро этого дня. Если отбой раньше 12:00, он считается временем после полуночи.
- **События на весь день** из .ics показываются в календаре, но не блокируют время для задач. При совмещении импортов они сравниваются только с такими же событиями на весь день.
- **Импорт:** пересечения со старыми импортированными событиями ищутся в пределах ±1 года от сегодняшнего дня. При совпадении у старой серии исключается одно вхождение, а разовое событие удаляется. Ручные (не импортированные) события импорт не трогает.
- Задача, перекрытая новым событием, переносится автоматически, если она не закреплена. Закреплённая получает предупреждение.
- **Автоперенос** срабатывает только на **новые** нарушения. Если вы сами поставили задачу на время с нарушением (например, выбрали вариант из «лучших из худших»), это нарушение считается принятым, и при обновлении страницы задача не двигается. Перенос идёт только в слот без нарушений. Если такого слота нет, задача **остаётся на месте** с ⚠ и плашкой, из календаря она не снимается.

## Не сделано

- Свои типы активности сверх трёх базовых (в ТЗ необязательно).

- Всё, что ТЗ относит к «вне рамок»: уведомления, синхронизация по ссылке, экспорт и т. д.
